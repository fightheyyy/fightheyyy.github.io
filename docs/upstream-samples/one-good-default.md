Options feel generous when you are building them. They can feel like homework when you are trying to use them.

## Choose a beginning

A default is a recommendation expressed through behavior. It should suit the common case, be easy to understand, and leave a clear path to change it.

For a reading interface, following the system color scheme is a useful beginning. A manual override can remain available without becoming the first thing a new reader must consider.

## Explain only the real tradeoff

If an option changes performance, privacy, or the meaning of the result, explain it. If it changes nothing the person can usefully reason about, perhaps it does not need to be an option yet.

## Revisit the evidence

Defaults are not permanent commitments. Watch how people use the product and adjust when the same friction appears repeatedly. The starting point should improve as your understanding improves.
