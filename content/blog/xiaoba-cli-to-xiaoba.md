小八是我养的猫。页面左上角的照片是它，旁边的像素猫是 xiaobaOS 的 App 图标。项目借用了它的名字。

我想做的小八，能记住之前聊过什么，知道还有哪些事情没做完。关掉终端、换一个入口，再找到它时，上次的事情还能接着往下做。现在离这个目标还有距离。

::callout
---
title: "XiaoBa 三阶段命名"
---
这三个名字对应不同的打算。

XiaoBa-CLI 是最早的命令行版本；xiaobaOS 是正在做的运行环境；等这些基础足够可靠了，我希望只叫它 XiaoBa。
::

1.  01
    
    XiaoBa-CLI
    
    一个可以理解命令、调用工具并完成任务的 Agent Runtime。
    
2.  02
    
    xiaobaOS
    
    正在做的运行环境，负责长期任务、电脑操作、运行记录和能力更新。
    
3.  03
    
    XiaoBa
    
    希望最终做成的小八：记得共同经历，换个入口也能接着相处。
    

## 第一阶段：先让它真的能做事

2026 年 4 月，我先把模型接进一个 Agent loop，让它能读文件、调用 Shell、使用 Skills，再把结果交回终端。那时要解决的都是执行问题：工具能不能调通，失败了会怎样，任务能不能做完。

```text
命令 → 模型 → Tool → 结果

打开终端时它出现
任务结束后它离开
```

从 CLI 开始，交互简单，可以先集中处理工具调用、错误返回、上下文压缩和日志。后面的记忆和长期任务都要用到这些东西。

只是任务结束后，程序也就退出了。如果希望小八一直在，就还得保存会话状态、处理后台任务，让下次启动能接上之前的工作。

## 第二阶段：从终端走到桌面和消息里

2026 年 7 月，我把项目和仓库改名为 xiaobaOS。那时已经有了终端之外的入口，继续叫 CLI 不太贴切。

桌面、Pet、CLI、飞书和微信需要共用运行状态。不同的专业能力需要组织起来，执行过程和产出文件要留得住，出错后还要能重跑。这些事逐渐占了开发的大头。

| 从 | 走向 | 需要补上的能力 |
| --- | --- | --- |
| 一次命令 | 长期运行 | 有时间、状态、中断与恢复 |
| 一个入口 | 多个 Surface | 在终端、桌面与消息平台保持同一运行边界 |
| 工具调用 | 电脑身体 | 浏览器、GUI、文件和工作平台成为感官与双手 |
| 运行日志 | 可验证经历 | Trace、Artifact 和交付事实支撑复盘 |
| 更新代码 | 更新与验收 | 把问题保存成 Case，用来验收候选改动 |

这里的 OS 指小八的运行环境：接入模型、工具和电脑，管理角色、Skills、记忆与评测。它运行在 Windows 或 macOS 之上。

## 现在最需要做的是整理已有系统

按这三个阶段来算，我还在第二阶段。xiaobaOS 已经有不少功能，但用起来、维护起来都还不够顺。

比如 Replay、Eval、Arena 和自进化分别长出了自己的 Runner、Schema、Decision 和 Scorecard。同一次运行的记录在几层之间反复包装，查一个结果往往要先弄清它是哪一层给出的。

```text
Case → Replay → Trace → Verify → Outcome

Test  = Implementation Correctness
Eval  = Agent Behavioral Capability
Arena = Agentic Eval
Self-Evolution = 发现问题、生成候选、调用评测、等待晋升
```

接下来要收掉这些重复实现。Runtime 执行任务，Trace 保存记录，Evaluation 给出评测结果。Arena 发现新问题后复用同一条评测路径，自进化也调用这条路径验收候选改动。

## 我希望以后的小八是什么样

将来使用小八时，我希望不必关心背后切换了哪个 Role、挂载了哪个 Skill，也不用知道 Replay 和 Promotion 怎么工作。一次会话换到另一个入口，事情应该能继续。

具体来说，我希望它能做到这些：

-   它记得自己是谁，也记得与你共同经历过什么。
-   它知道答应过哪些事情，哪些目标还没有完成。
-   它可以通过浏览器、桌面、文件和消息平台感知并行动。
-   它知道自己的权限、风险和不确定性，重要动作会询问你。
-   它能把失败变成经验，把重复经验变成能力，同时不随意改写自己的核心。
-   无论你从哪个入口找到它，面对的都是同一个 XiaoBa。

我也希望它的能力能逐渐接近 AGI。不过，对这个项目更具体的期待是：小八能长期留在电脑里，记得我们的事情，能做事，也知道什么时候需要我来决定。上面这些仍是目标。

## 为什么是这只猫

现实里的小八不会写代码，也不懂 Case 和 Trace。它每天在我身边，有自己的习惯和性格。我熟悉的是这只猫，而不是每次见面都重新开始的一段关系。

这也是我把它的名字借给项目的原因。我希望电脑里的小八，慢慢也能有这种熟悉感。要做到这一点，先得把那些不太有趣的会话、记忆和恢复问题处理好。

眼下先把重复的评测路径整理好，让一次任务从执行到验收都能查清楚。之后再谈下一步。
